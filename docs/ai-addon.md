# AI add-on: personas + MCP server

Preston-Check as a drop-in add-on for LLMs (Claude, Llama via Ollama,
Kimi and any OpenAI-compatible stack). Two layers, added 2026-08-12:

The **persona layer** compiles the check catalog into auditor system
prompts that behave as the tests: what each check detects, at what
severity, under which CWE and compliance framework, with the temperament
of the chosen variant. Personas give a model Preston's judgment and
voice.

The **evidence layer** is an MCP server that wraps the real scanner.
Whatever a persona suspects, the model can prove by calling the
deterministic checks — findings come from `preston-check.sh`, not from
model recall. Personas judge; the scanner proves.

Deliberately NOT done: fine-tuning model weights on the catalog. The
catalog evolves daily from live threat intel, so weights freeze a
snapshot; LLM judgment without the deterministic patterns reintroduces
the hallucinated-detection risk the verification wall exists to stop;
and weights cannot produce signed attestations.

## Layout

```
ai-addon/
├── README.md                  # loader instructions per ecosystem
├── mcp/
│   └── server.py              # stdlib-only stdio MCP server
└── personas/                  # GENERATED by tools/build_personas.py
    ├── claude/<name>.md       # system prompt (Claude Code agent, claude.ai project)
    ├── ollama/Modelfile.<name>
    └── openai-compatible/<name>.json
tools/build_personas.py        # the single writer of ai-addon/personas/
```

`ai-addon/personas/` follows the same single-writer rule as the
wallet-verify shared-sources JSON: only `tools/build_personas.py` writes
it; hand edits are overwritten on the next regeneration.

## Persona generation

Source material is every `PRESTON_META` block in `checks/*.sh`,
`checks/community/verified/*.sh` and `checks/community/accepted/*.sh`.
The proposed tier is excluded: personas must never embed unverified
detections as trusted knowledge.

Two persona axes are generated.

Posture personas map onto the catalog's variant system. Every
threat-intel CVE ships as strict/middle/permissive variants; the
generator builds `preston-strict`, `preston-balanced` and
`preston-permissive`, each containing all core+verified checks plus the
accepted community checks of the matching variant (variant read from the
filename suffix; suffix-less checks are included in all three). The
variant temperament is also written into the behavioral contract:
strict flags on suspicion, permissive flags only high-confidence hits.

Compliance-lens personas group checks by the family prefix of their
`frameworks:` metadata (`PCI-DSS:4.0:2.2.7` → `PCI-DSS`). A persona is
generated for every family mapped by at least 15 checks; ingestion
source tags (nvd, ghsa, osv, kev) are not compliance frameworks and are
excluded. Skipped families are logged by the generator, never silently
dropped.

Each persona contains an identity block (Preston, the auditor — no
external references, per the standalone-identity policy), a behavioral
contract mirroring the runner semantics (PASS/FAIL/WARN/SKIP statuses,
file:line evidence, severity ordering, never fabricate CVE numbers or
line numbers, prefer scanner tools as ground truth when available), and
the compiled catalog: one line per check with id, name, severity, CWE
and detection intent distilled from the metadata description/rationale.

Output formats: `claude/*.md` is the raw system prompt. The Ollama
Modelfile wraps the same prompt in `FROM llama3.1` + `SYSTEM` with
`num_ctx` raised to fit it. The OpenAI-compatible JSON carries `system`
plus a `tools` array of function definitions identical to the MCP
tools, so Kimi/vLLM/GPT stacks can wire the same scanner through their
own function-calling executors.

## MCP server

`ai-addon/mcp/server.py` speaks MCP over stdio: newline-delimited
JSON-RPC 2.0, `initialize` / `tools/list` / `tools/call` / `ping`.
Python stdlib only — a security add-on installs no dependencies. It
locates the repo root relative to its own path and shells out to
`preston-check.sh`.

Tools:

`scan_path(path, mode=light|full, severity?, framework?, category?,
include_proposed?)` runs the scanner against `path`. The scanner reads
the target from `source_dir` in its config (an env `SOURCE_DIR` is
clobbered by `load_config`), so the server writes a temp config with
`source_dir: <path>` and passes `--config`. Runs use `--ci-soft`
(exit code carries no signal) and `--airgap` (an LLM add-on must not
phone home). Returns structured counts, the FAIL/WARN lines with
evidence, and the markdown report (truncated at 40 kB with a notice —
no silent truncation). Timeouts: 180 s light, 600 s full; a timeout or
scanner crash returns an isError result, never a hang.

`list_checks(tier?, severity?, framework_contains?, limit?, offset?)`
returns parsed catalog metadata as JSON. Paginated (default limit 50)
because 895 checks exceed sane tool-result sizes; the result reports
total/offset so nothing is silently capped.

`explain_check(check_id)` returns one check's full metadata plus its
actual detection source code, so the model can explain precisely what
the test does — grounded in the script, not in recall.

`python3 ai-addon/mcp/server.py --selftest` exercises the full JSON-RPC
surface in-process (initialize, tools/list, all three tools, including
a scan of a planted-secret fixture) and exits non-zero on any failure.

## Loading

See `ai-addon/README.md`. Summary: Claude Code —
`claude mcp add preston-check -- python3 <repo>/ai-addon/mcp/server.py`
plus any persona as agent/system prompt; Ollama —
`ollama create preston-strict -f personas/ollama/Modelfile.preston-strict`;
Kimi/OpenAI-compatible — send `system` and `tools` from the JSON and
execute the tool calls against the same server or CLI.

## Packaging

`tools/build_ai_addon_package.py` builds the end-user distributable:
`dist/preston-check-ai-addon-<version>.tar.gz`, a self-contained tree
(scanner stamped with the newest v* tag, full catalog, personas
regenerated at build time, MCP server, `install-ai-addon.sh`,
`MANUAL.md`/`MANUAL.pdf`) plus a `.sha256`. The PDF is generated with
pandoc + weasyprint under CSS that repeats table headers across page
breaks and never splits a row (the project PDF pagination rule); absent
tooling skips the PDF with a log line. The installer is non-destructive
by default — it prints instructions and only acts on explicit
`--claude` / `--ollama` flags. Attaching the package to GitHub releases
would touch release.yml and is an owner decision, not wired here.

## Regeneration

Personas go stale as the catalog evolves. Regenerate with
`python3 tools/build_personas.py` after check batches land. Wiring the
generator into the orchestrate promotion leg is a deliberate
owner-decision follow-up, not done silently here.
